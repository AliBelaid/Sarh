# الفصل السادس — النتائج والخاتمة

## 6.1 ملخّص ما أُنجز

أُنجزت منصّة **صَرح** كنظام متكامل يضم: خدمة خلفية بـ ASP.NET Core 8، تطبيق ويب موحّداً بـ Angular 21 لكل الأدوار، تطبيق محمول بـ Flutter، وقاعدة بيانات SQL Server بطبقة جغرافية وسجل تدقيق غير قابل للتعديل. غطّى النظام دورة حياة العقار كاملة (تقديم → مراجعة → اعتماد → صكّ موقّع → تحقق عام)، وإصدار الهوية الرقمية على بطاقات NFC مقاومة للاستنساخ.

## 6.3 أبرز التحديات

- **تهيئة قاعدة البيانات بشكل محمول**: حُلّت بمُهيّئ EF يطبّق ملفات T-SQL المضمّنة مباشرة ويختم سجل الترحيلات.
- **توقيت إقلاع خرائط Leaflet** داخل `@if`: حُلّ بتأجيل التهيئة + `invalidateSize()`.
- **تمييز التداخل عن التجاور**: استُخدمت **مساحة التقاطع** (> 1م²) بدل مجرّد التقاطع، حتى لا تُعلَّم الأراضي المتجاورة خطأً.
- **ترميز UTF-16** الذي أفسد ملفات نصية: حُلّ بإعادة الترميز إلى UTF-8.
- **عنوان API على الأجهزة الفعلية في Flutter**: حُلّ بحلّال عنوان تلقائي.

## 6.4 الأعمال المستقبلية (Future Work)

1. **التكامل مع هوية وطنية رسمية** عند إطلاقها، والهجرة دون فقد بيانات (الحقل `legacy_national_no` مُهيّأ).
2. **شبكة بلوكتشين إنتاجية** تحلّ محل الطبقة البديلة (Stub) لسكّ سجلات الملكية.
3. **تفعيل ACA-Py الإنتاجي** لإصدار الاعتمادات القابلة للتحقق على نطاق واسع.
4. **الرسم بالمشي (GPS Walk)** لحدود الأراضي الكبيرة عبر الهاتف.
5. **اللحظية (Realtime)** عبر SignalR للإشعارات الفورية.
6. **فحص الفيروسات** للمرفقات (ClamAV) ولوحات تقارير أوسع.

## 6.5 الخلاصة

قدّم مشروع **صَرح** نموذجاً عملياً لرقمنة السجل العقاري الليبي بضمانات تقنية قوية ضد التزوير والازدواجية، مع هوية رقمية مقاومة للاستنساخ وتحقق عام شفّاف، وبأساس مكاني دقيق يحمي الملكية. البنية معيارية وقابلة للتوسّع، ومهيّأة للتكامل المستقبلي مع المنظومات الوطنية.
