# الفصل الثاني — تحليل المتطلبات

## 2.1 الأدوار والصلاحيات (Roles)

الصلاحيات لا تُفحص بنصوص حرّة في الكود، بل عبر **خريطة صلاحيات JSON** مخزّنة على `officers.permissions`، وتُفرض في الواجهة عبر دالة موحّدة لتحديد ما يصل إليه كل دور.

| الدور | أبرز الصلاحيات |
|------|------------------|
| `citizen` | تقديم عقار، متابعة طلباته، عرض هويته الرقمية. |
| `registry_officer` | مراجعة طلبات منطقته، تدقيق المستندات والحدود، تعديل الحدود. |
| `reviewer` | مراجعة/تدقيق ضمن المنطقة. |
| `department_manager` | الاعتماد النهائي وإصدار الصكّ/سكّ الرخصة. |
| `id_issuer` | إصدار بطاقات الهوية الرقمية (NFC). |
| `super_admin` | كل الصلاحيات + إدارة المستخدمين. |
| `auditor` | الاطّلاع على سجل التدقيق والتقارير. |

## 2.2 المتطلبات الوظيفية (Functional Requirements)

### وحدة المواطنين والهوية (Citizens & Digital ID)
- FR-1: تسجيل/إدارة بيانات المواطن مع الاحتفاظ بحقل `legacy_national_no` لإعادة الربط مستقبلاً.
- FR-2: إصدار هوية رقمية برقم بصيغة `LY-XX-YYYY-NNNNNN-D`.
- FR-3: إصدار بطاقة NFC (NTAG 424 DNA) مرتبطة بالهوية مع PIN وصلاحية.
- FR-4: تسجيل دخول المواطن برقم الهوية الرقمية + PIN، والموظف بالبريد + كلمة المرور.

### وحدة العقارات (Properties)
- FR-5: تقديم عقار برسم **مضلّع الحدود** على الخريطة (٣ نقاط على الأقل).
- FR-6: **اشتقاق المساحة من المضلّع** وإعادة حسابها على الخادم والتحقق ضمن ±5%.
- FR-7: **إلزامية المرفقات**: صورة موقع + شهادة كروكي على الأقل، وإلا يُرفض الطلب.
- FR-8: **منع تطابق الإحداثيات** (مركز القطعة) لعقارين معتمدَين (رفض صارم).
- FR-9: **كشف تداخل الأراضي** وتمييز حالته: «خلل في الملكية» عند التداخل مع عقار معتمد، و«تضارب في الموقع» عند تداخل عقارين غير معتمدَين.
- FR-10: مراجعة الطلب (اعتماد/رفض/طلب توضيح) مع ملاحظة ورقم قرار.
- FR-11: تعديل/إعادة رسم حدود العقار من قبل الموظف.

### الخرائط والتحقق (Map & Verify)
- FR-12: خريطة مساحية للموظف تعرض كل قطع منطقته مع تمييز الحالة (سليم/نزاع/قيد المراجعة/تضارب).
- FR-13: خريطة عامة تعرض القطع الصادرة صكوكها فقط، دون أي بيانات شخصية.
- FR-14: بوابة تحقق عامة عبر رمز QR تتحقق من توقيع الصكّ.

### الإدارة والتدقيق (Admin & Audit)
- FR-15: لوحة إدارة وتقارير.
- FR-16: تسجيل كل عملية كتابة في **سجل تدقيق غير قابل للتعديل**.
- FR-17: إشعارات داخلية للمراجعين عند ورود طلب/تضارب.

## 2.3 المتطلبات غير الوظيفية (Non-Functional Requirements)

| المعرّف | المتطلب |
|---------|---------|
| NFR-1 (لغة) | كل الواجهات بالعربية RTL؛ اللاتينية للرموز والمعرّفات التقنية فقط. |
| NFR-2 (أمان) | JWT (HS256) بلا بيانات شخصية، bcrypt لكلمات المرور، CORS مقيّد، تحديد معدّل على `/auth/*` و`/properties`. |
| NFR-3 (مقاومة الاستنساخ) | بطاقات NTAG 424 DNA مع رسالة SUN وعدّاد متدحرج يُتحقق منه على الخادم. |
| NFR-4 (سلامة المستندات) | كل صكّ موقّع PAdES ويحمل QR للتحقق. |
| NFR-5 (سلامة التدقيق) | سجل التدقيق إلحاقي فقط (لا UPDATE/DELETE). |
| NFR-6 (الدقة المكانية) | المساحة من المضلّع، والتحقق من التداخل والمركز عبر `geography`. |
| NFR-7 (الأداء) | ترقيم بالمؤشّر (cursor) لا الإزاحة على الجداول الكبيرة. |
| NFR-8 (قابلية النقل) | تهيئة قاعدة البيانات عبر ترحيلات EF تعمل على أي جهاز فيه .NET 8 SDK + SQL Server. |
| NFR-9 (إعادة الإصدار) | إمكانية الهجرة لهوية وطنية مستقبلية دون فقد بيانات. |

## 2.4 حالات الاستخدام (Use Cases)

| المعرّف | الفاعل | الحالة |
|---------|--------|--------|
| UC-1 | مواطن | تسجيل الدخول بالهوية + PIN |
| UC-2 | مواطن | تقديم عقار جديد ورسم حدوده وإرفاق المستندات |
| UC-3 | مواطن | متابعة حالة الطلب |
| UC-4 | موظف سجل | فتح طابور المراجعة واختيار طلب |
| UC-5 | موظف سجل | فحص الخريطة والتأكد من عدم وجود تداخل |
| UC-6 | موظف سجل | اعتماد/رفض/طلب توضيح |
| UC-7 | مدير الإدارة | الاعتماد النهائي وإصدار الصكّ |
| UC-8 | مُصدِّر هوية | إصدار بطاقة NFC للمواطن |
| UC-9 | العموم | التحقق من صكّ عبر QR |
| UC-10 | مدقّق | الاطّلاع على سجل التدقيق |

### مثال مفصّل — UC-2 «تقديم عقار»
1. يسجّل المواطن الدخول ويفتح شاشة «عقار جديد».
2. يرسم مضلّع الحدود على الخريطة (تظهر الأراضي المسجّلة كخلفية رمادية لتفادي الرسم فوقها).
3. يُدخل النوع والمنطقة والمساحة، ويرفق صورة الموقع والكروكي.
4. عند الإرسال: يتحقق الخادم من المساحة، ويرفض تطابق المركز، **ويفحص التداخل**؛ فإن وُجد يُنبَّه المراجعون ويوسَم العقار بحالة التضارب المناسبة.
5. يُنشأ طلب تسجيل بحالة `pending` ويُشعَر مراجعو المنطقة.

## 2.5 قصص المستخدمين (User Stories) — أمثلة
- «كمواطن، أريد رسم حدود أرضي على الخريطة بدقّة كي تُحسب مساحتها تلقائياً.»
- «كموظف سجل، أريد رؤية كل القطع المجاورة على الخريطة كي أكتشف أي تداخل قبل الاعتماد.»
- «كمشترٍ، أريد التحقق من صحة صكّ عبر مسح رمز QR دون الحاجة لحساب.»

## 2.6 القيود (Constraints)

مستمدّة من وثيقة قيود البناء (`CLAUDE.md`)، وهي قيود **غير قابلة للتفاوض**:
1. العربية أولاً RTL لكل الواجهات.
2. الاحتفاظ بـ `legacy_national_no` لإعادة إصدار الهوية مستقبلاً.
3. لا عقارَين معتمدَين بنفس المركز؛ التداخل يثير **تحذيراً للمراجع** (لأن الصكوك الورقية القديمة قد تتعارض شرعياً) — وقد طُوّر إلى تمييز حالتَي «خلل في الملكية» و«تضارب في الموقع».
4. بطاقات NTAG 424 DNA فقط مع SUN وعدّاد متدحرج.
5. صكوك موقّعة PAdES مع QR.
6. سجل التدقيق إلحاقي فقط.
7. لا فحص أدوار بنصوص حرّة — عبر خريطة الصلاحيات.
8. المساحة من المضلّع لا من الطول×العرض.
9. كل تقديم عقار يحمل دليلاً (صورة + كروكي).
